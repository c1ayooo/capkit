# 究极渗透能力包实现方案

> 目标：把 capkit 建成一套**纯后端、可 import、覆盖"信息收集→漏洞利用→凭据→后渗透→权限维持→痕迹清理→免杀投递→内网收集→杀软对抗"全链路**的能力集合。
> 本文基于 2026-10-19 对 `/home/c1ay/4zreco` 与 `/home/c1ay/4zrec/capkit` 的实测盘点，以及 28 个开源项目的 star/语言/许可证核对结果。

---

## 一、定位与边界

capkit 是库，不是平台。

- 不含 HTTP 服务、不含 UI、不含用户体系。宿主 import 后自行暴露 API。
- 认证分两层：平台侧（谁能打）归宿主；目标侧（打的时候用什么身份）归 capkit。
- 发现层已有成熟实现（nuclei 生态），不重造；capkit 的增量在**利用、会话、投递、后渗透**。
- 整体交付，不承诺单 kit 独立可用。

### 3.2 分层

```
契约层  core.go / port.go / identity.go / session.go   不含实现

门禁层  gates/*                                           scope→approval→ratelimit→audit
适配层  adapters/*                                        httpx / exec / pg / memstore
组装层  all/*                                             RegisterFull 一把梭
```

**依赖方向单向：kits → capkit 根，禁止 kits 之间横向 import。**

### 4.12 杀软与 EDR 识别（只做识别，不做对抗）

范围已明确：免杀与杀软对抗不做，只做目标环境的安全软件信息收集。理由是识别是确定性工程（读进程、读服务、读注册表），对抗是军备竞赛（做完即失效，且法律风险高）。

| 能力 | 说明 |
|---|---|
| 进程识别 | 进程名、PID、可执行路径、签名者、命令行 |
| 服务识别 | 服务名、显示名、二进制路径、启动类型 |
| 驱动识别 | 已加载驱动、文件路径、数字签名 |
| 注册表识别 | Windows 下安全软件键位与安装信息 |
| 产品映射 | 360、火绒、Defender、卡巴斯基、CrowdStrike、Sangfor、天擎、Symantec、McAfee、趋势 |
| 版本与规则日期 | 从文件版本、更新目录、服务参数推断 |
| 检测面提示 | 根据产品类型与是否 EDR 类，提示"可能拦截哪些行为"，明确标注为推测而非保证 |

**明确不做**：AMSI 绕过、ETW patch、BYOVD、内存扫描规避、成品免杀载荷、行为规避。这些不进 capkit，也不在本次实施范围。

归属：并入 `inet_host_profile` 的杀软面（见 10.3），不单独成 kit。

## 五、关键契约

### 5.1 Session（后渗透根契约）

```go
type Session interface {
    Exec(ctx context.Context, cmd string, opts ExecOpts) (Output, error)
    Info() SessionInfo
    Close() error
}

// 可选能力，调用方类型断言探测，不支持则 fallback 到 Exec + base64
type Uploader   interface{ Upload(ctx context.Context, src io.Reader, remote string) error }
type Downloader interface{ Download(ctx context.Context, remote string) (io.ReadCloser, error) }
type Tunneler   interface{ Tunnel(ctx context.Context, spec TunnelSpec) (Tunnel, error) }
```

新增 adapter 只需实现三个方法，其余自动继承。

### 5.2 Identity（目标侧身份）

```go
type Identity interface {
    Headers(ctx context.Context) (http.Header, error)
    Refresh(ctx context.Context) error
    Scope() IdentityScope
}

type AuthFlow interface {
    Kind() string   // form | json | oauth | cas | bearer
    Login(ctx context.Context, creds Credentials) (Identity, error)
}
```

宿主实现具体站点的 `AuthFlow`；capkit 提供 Cookie 罐、CSRF 提取、Token 刷新判定。

### 5.3 Planner（下一步建议）

```go
type NextStep struct {
    Tool          string
    Reason        string
    Preconditions []string
    Risk          Risk
    Params        json.RawMessage
}

type Planner interface {
    Suggest(ctx context.Context, f Finding) ([]NextStep, error)
}
```

输入 Finding，输出可选动作。agent 与宿主共用同一份数据。

### 5.4 Finding（统一漏洞结论）

```go
type Finding struct {
    Target    Target
    Kind      string   // cmdi | sqli | ssti | lfi | ssrf | upload | deser | ...
    Fingerprint string // 目标+类型+参数+路径 的归一化指纹，用于跨源去重
    Confirmed bool
    Payload   string
    Evidence  []string
    Source    string   // nuclei | exploitkit | yuque-template | manual
}
```

`Fingerprint` 用于把 nuclei、exploitkit、语雀模板的多源命中合并成一条。

### 5.5 工具输出契约（agent 调用的核心）

agent 调工具与人类点按钮的差别在于：agent 必须能从一次返回里判断"做成了没有、为什么没成、能不能重试、下一步干什么"。所以输出不能是裸数据，必须是一个**固定信封 + 受 schema 约束的载荷**。

#### 5.5.1 信封结构

```go
type Result struct {
    OK        bool             `json:"ok"`
    Status    Status           `json:"status"`
    Summary   string           `json:"summary"`              // ≤200 字，给 agent 直接读
    Data      json.RawMessage  `json:"data,omitempty"`       // 结构化载荷，受 output_schema 约束
    Findings  []Finding        `json:"findings,omitempty"`   // 归一化结论
    Evidence  []EvidenceRef    `json:"evidence,omitempty"`   // 只给引用，不内联大内容
    Next      []NextStep       `json:"next,omitempty"`       // 建议的下一步动作
    Truncated bool             `json:"truncated,omitempty"`
    Page      *Page            `json:"page,omitempty"`
    Error     *ToolError       `json:"error,omitempty"`
    Meta      Meta             `json:"meta"`
}
```

四个字段是硬性的：`Status`、`Summary`、`Error`、`Meta`。缺任何一个，agent 就没法正确决策。

#### 5.5.2 Status 六态

```go
type Status string

const (
    StatusSuccess     Status = "success"      // 完成，无风险
    StatusPartial     Status = "partial"      // 部分完成，例如 10 个目标里 2 个超时
    StatusFailed      Status = "failed"       // 失败，可能可重试
    StatusBlocked     Status = "blocked"      // 被门禁拦下：scope / approval / ratelimit
    StatusNeedHuman   Status = "need_human"   // 高危动作，需要人工确认
    StatusUnavailable Status = "unavailable"  // 依赖缺失，例如 nuclei 未安装
)
```

为什么要六态而不是一个 bool：agent 对六种状态的处理路径完全不同。`blocked` 要换目标或申请授权，`need_human` 要挂起等确认，`unavailable` 要报告环境问题，`failed` 才考虑重试。统一成 `OK=false` 会让 agent 一律重试，撞在 scope 校验上死循环。

#### 5.5.3 错误分类

```go
type ToolError struct {
    Code         string `json:"code"`           // 机器可判的枚举
    Message      string `json:"message"`        // 一句话，给 agent 读
    Retryable    bool   `json:"retryable"`
    RetryAfterMS int    `json:"retry_after_ms,omitempty"`
    Hint         string `json:"hint,omitempty"`  // 参数该怎么改
    Detail       string `json:"detail,omitempty"` // 给开发者，不喂给 LLM
}
```

`Code` 固定枚举，不允许自由文本：

`scope_denied`、`approval_required`、`rate_limited`、`target_unreachable`、`timeout`、`tool_missing`、`bad_input`、`upstream_error`、`evidence_write_failed`、`internal`。

`Hint` 是给 agent 的修正建议，例如 `bad_input` 时说明"inject_point.url 缺少 {{inject}} 占位符"。没有 Hint，agent 只能盲试。

#### 5.5.4 截断与分页

大输出分两级处理：

```go
type Page struct {
    Total   int    `json:"total"`
    Cursor  string `json:"cursor,omitempty"`
    HasMore bool   `json:"has_more"`
}
```

规则：

- `Data` 单次上限 8KB，超出截断并置 `Truncated=true`，同时在 `Page.Total` 给出真实总数
- 列表类结果（URL、端口、模板命中）超过 100 条必须分页，用 `Cursor` 续取
- 正文、响应体、文件内容一律不进 `Data`，只进证据库，返回 `EvidenceRef`

```go
type EvidenceRef struct {
    ID       string `json:"id"`
    Kind     string `json:"kind"`     // http_exchange | file | command_output | scan_log
    Size     int    `json:"size"`
    SHA256   string `json:"sha256"`
    Preview  string `json:"preview,omitempty"` // ≤200 字
}
```

#### 5.5.5 长任务

超过 30 秒的操作（nuclei 全量扫、sqlmap 拖库、msf 执行）不要阻塞返回：

```go
type JobRef struct {
    JobID    string `json:"job_id"`
    PollAfterMS int `json:"poll_after_ms"`
}
```

返回 `StatusPartial` + `JobRef` 放进 `Data`，agent 用 `job_status` 轮询。轮询接口同样返回 `Result` 信封，`Status` 在 running 与终态之间切换。

#### 5.5.6 输出 schema 也要有契约

`contracts/` 新增 `output.json`：每个工具的 `Data` 必须匹配它自己声明的 `output_schema`。这样 agent 在调用前就知道返回长什么样，不用靠试。

`ToolSpec` 相应增加一个字段：

```go
OutputSchema json.RawMessage `json:"output_schema"`
```

宿主可以在 CI 里用 schema 校验每个工具的真实返回，防止实现漂移。

#### 5.5.7 Meta

```go
type Meta struct {
    Tool       string `json:"tool"`
    Version    string `json:"version"`
    DurationMS int64  `json:"duration_ms"`
    Requests   int    `json:"requests,omitempty"`   // 打了多少个请求
    Target     string `json:"target,omitempty"`
    GateTrace  []string `json:"gate_trace"`         // scope/approval/ratelimit 各阶段耗时
}
```

`Requests` 很重要：agent 需要知道自己刚才消耗了多少请求预算，才能决定还敢不敢继续。`GateTrace` 让"为什么这么慢"可查。

#### 5.5.8 一个真实返回示例

```json
{
  "ok": true,
  "status": "success",
  "summary": "目标 /api/exec 存在命令注入，已用 id 命令确认回显，payload 为 ;id",
  "findings": [{
    "kind": "cmdi",
    "target": "https://example.com/api/exec",
    "fingerprint": "cmdi|example.com|/api/exec|cmd",
    "confirmed": true,
    "payload": ";id",
    "source": "exploitkit"
  }],
  "evidence": [{"id": "ev_7f3a", "kind": "http_exchange", "size": 1820, "sha256": "..."}],
  "next": [
    {"tool": "cmdi_execute", "reason": "已验证注入，可执行任意命令", "risk": "high", "preconditions": ["finding.confirmed"]},
    {"tool": "cmdi_webshell_drop", "reason": "获取持久访问", "risk": "high", "preconditions": ["session.writeable"]}
  ],
  "meta": {"tool": "cmdi_probe", "version": "0.3.0", "duration_ms": 842, "requests": 7, "gate_trace": ["scope:1ms", "ratelimit:0ms", "audit:2ms"]}
}
```

agent 读完这个返回，知道：成了、什么漏洞、证据在哪、能接着做什么、花了几次请求。不需要再读文档或猜。

### 5.6 幂等与去重

每个工具调用带 `idempotency_key`（由 target + tool + params 哈希生成）。同一 key 在 N 分钟内重复调用，直接返回上次结果并置 `Meta.Cached=true`。

理由：agent 会重试，尤其是在超时后。没有幂等，一次命令注入探测会被打三遍，既浪费请求预算又在目标日志里留下明显痕迹。

`Finding.Fingerprint` 负责跨工具去重：nuclei、exploitkit、语雀模板命中同一个漏洞时，按 target + kind + param + path 归一化，合并成一条，`Source` 记多个来源。

## 十、扩展能力包（v2，已确认实施）

本章是 v1 的增补。以下七项均已确认为实施范围，不再作为「不做什么」的边界。

### 10.1 云控制台接管

现状：`cloudkit` 未落地，零实现。

新增 `cloud_console_login`（risk: high，强制 approval）。

技术路径，各云联合身份换登录态：

| 云 | 换取方式 | 控制台入口 |
|---|---|---|
| 阿里云 | STS `AssumeRole` 取临时凭证，`signin.aliyun.com/federation` 的 `GetSigninToken` 换 token | `Action=Login` 拼跳转 URL |
| AWS | `sts:GetFederationToken`，`signin.aws.amazon.com/federation?Action=getSigninToken` | `Action=login` 拼跳转 URL |
| 腾讯云 | `cam:GetFederationToken` 取临时凭证 | 控制台登录链接，端点需实测确认 |
| 华为云 | `CreateTemporaryAccessKeyByAgency` | `auth.huaweicloud.com/authui/federation/login` |

返回：临时登录 URL、生效身份、权限范围、有效期。

硬约束：

- URL 内含临时凭据，禁止明文进证据库，必须经 `sealer` 加密存储
- `Summary` 只报账号 ID 与有效期，不出现任何凭证片段
- 登录 URL 有效期通常 15 分钟到 12 小时，过期必须重新换取，不做本地缓存

### 10.2 容器逃逸执行

现状：`containerkit` 已有 `container_escape_check` 与 `container_escape_plan`，缺执行。

新增 `container_escape_exec`（risk: high）。

按 plan 给出的路径执行单条：

- docker.sock：起 privileged 容器挂宿主 `/`，执行命令，退出即删
- privileged：`cgroup release_agent` 或 `core_pattern` 写宿主命令
- hostPath 挂载：写宿主 cron 或 `authorized_keys`
- k8s：建 privileged pod 挂 hostPath，执行后删 pod

强制字段 `rollback`，每个动作必须给出对应还原命令（删容器、删 pod、还原 `release_agent`、删除写入的文件）。没有回滚方案的路径不允许执行。

### 10.3 跳板机信息收集

现状：`internalnetkit` 有 `inet_local_info` 等基础探测，缺深度采集。

新增 `inet_host_profile`（risk: medium），一次采集五块，单块失败用 `StatusPartial`：

- 系统面：发行版、内核、补丁、架构、启动时间、虚拟化类型
- 杀软面：进程名、服务名、驱动、注册表键位映射到产品（360、火绒、Defender、卡巴、CrowdStrike、Sangfor）
- 网络面：网卡、路由、ARP、DNS、代理配置、可达网段推导
- 敏感文件：`.ssh`、`.aws`、`.kube`、`.docker`、`.git-credentials`、shell 历史、常见配置文件
- 凭据线索：环境变量中的连接串、配置文件明文口令、密钥路径

输出结构化数据 + 证据引用，正文不进 `Data`。

### 10.4 隧道自动搭建

现状：`shellkit` 有 `tunnel_open`，选型靠调用方。

新增 `tunnel_auto`（risk: medium）：

1. 探测：TCP 直出、HTTP 代理、DNS 出网、本机 bind 端口可用性
2. 选型：HTTP 出网用 chisel，可开 TUN 用 ligolo，多协议用 gost，仅 DNS 用 DNS 隧道
3. 部署：生成目标侧命令、启动、验证连通、返回本地 socks 地址
4. 回收：同时返回清理命令，与 `cleanupkit` 打通

### 10.5 反序列化验证

现状：`exploitkit` 有 `deser_generate`，只造 payload。

新增 `deser_verify`（risk: high）：

- 生成层复用 `deser_generate`（ysoserial、phpggc、ysoserial.net）
- 投递层按位置适配：body 原生流、header、cookie、base64 包装、URL 编码
- 判定层三选一：回显特征串、OAST 回连（复用 `oastkit`）、时间延迟基线对比
- 输出：可用 gadget 链、payload、判定依据、证据 ID

### 10.6 AD 域利用

现状：`latkit` 有 psexec、wmiexec、smbexec、winrm、pass-the-hash、kerberoast、asrep、dcsync。

新增五个：

- `ad_adcs_attack`：Certipy 的 ESC1 至 ESC8，请求证书取域管
- `ad_ticket`：Golden Ticket、Silver Ticket、S4U2Self、S4U2Proxy
- `ad_delegation`：非约束委派、约束委派、RBCD
- `ad_acl_abuse`：GenericAll、WriteDACL、ForceChangePassword、AddMember
- `ad_bloodhound_collect`：SharpHound 数据采集加最短路径分析

依赖 impacket 与 Rubeus 的 subprocess 调用，GPL 与未声明许可的部分只走进程边界。

### 10.7 C2 接入

现状：`sessionkit` 有 cli、ssh、smb、winrm、webshell 五种 adapter，无 C2。

新增两个 adapter，复用现有 `session_exec`、`session_upload`、`tunnel_open`：

- `sliver`：走 gRPC。Sliver 是 GPL-3.0，只允许通过协议通信，禁止 import 其 Go 代码，protobuf 自行生成 client
- `msf`：走 RPC，msgpack 编码

接入后 `session_open` 的 `kind` 增加 `sliver`、`msf` 两个取值，上层调用代码不变。
