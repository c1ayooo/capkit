# 宿主接线指南

面向「把 capkit 挂进宿主平台」的工程师。目标：一次接线，之后加 kit 不用改宿主代码。

配套文档：
- [工具调用协议](./工具调用协议.md) —— 调用方（agent / 宿主 BFF / 前端）看到的统一契约
- [前端展示设计方案](./前端展示设计方案.md) —— 工具台与结果展示的界面方案

> 文中带 `internal/…`、`web/…` 前缀的路径属于**接入 capkit 的宿主仓库**（本文以 4zrec 为例），capkit 模块本身只含 `capkit/` 下的内容。

## 0. 一分钟版

```go
import (
    "github.com/c1ayooo/capkit"
    "github.com/c1ayooo/capkit/adapters/auditlog"
    "github.com/c1ayooo/capkit/adapters/exec"
    "github.com/c1ayooo/capkit/adapters/httpx"
    "github.com/c1ayooo/capkit/adapters/sealer"
    "github.com/c1ayooo/capkit/adapters/settings"
    "github.com/c1ayooo/capkit/all"
    "github.com/c1ayooo/capkit/gates"
    "github.com/c1ayooo/capkit/kits/sessionkit"
    "github.com/c1ayooo/capkit/runtime"
)

scope := myScope                        // capkit.ScopeChecker，宿主实现
limiter := gates.NewLimiter()
audit := auditlog.NewMemory()           // 生产换成宿主落库实现
seal, _ := sealer.New(masterKey)        // 32 字节

// 会话：宿主决定有哪些 opener，kit 不自己开连接
mgr := sessionkit.NewManager(nil, nil)
mgr.RegisterOpener("ssh", &sessionkit.SSHOwner{HostKeyCallback: pinned})
mgr.RegisterOpener("winrm", &sessionkit.WinRMOpener{HTTP: httpx.New(scope, limiter, audit)})
mgr.RegisterOpener("smb", &sessionkit.SMBOpener{Runner: exec.New(scope, limiter, audit)})

reg := capkit.NewRegistry()
if err := all.RegisterFull(reg); err != nil { return err }

rt, err := runtime.New(runtime.Config{
    Scope: scope, Approval: myApproval, Limiter: limiter, Audit: audit,
    HTTP: httpx.New(scope, limiter, audit), Fetcher: myFetcher,
    Processes: exec.New(scope, limiter, audit), Binaries: myBinaries,
    Settings: settings.New(myStore), Sealer: seal, Evidence: myEvidence,
    Artifacts: myArtifacts, Sessions: mgr,
    Fingerprints: myFingerprints, Templates: myCatalog,
    TemplateEngines: map[string]capkit.TemplateEngine{"http": httpEngine, "nuclei": nucleiEngine},
}, reg)
```

`runtime.New` 会在任何声明了 `Requires` 的 kit 缺端口时**直接返回错误**（fail closed），不会等跑到一半才失败。缺哪个端口，错误信息里点名。

## 1. 端口清单（Requires ↔ Deps ↔ Config）

`Manifest.Requires` 里的字符串就是 `Registry.Validate` 认识的 key，映射关系如下（见 `registry.go`）：

| Requires | `capkit.Deps` 字段 | `runtime.Config` 字段 | 谁在用 | 不接的后果 |
|---|---|---|---|---|
| `scope` | `Scope` | `Scope` | 全部目标型工具 | `runtime.New` 报错（必填） |
| `limiter` | `Limiter` | `Limiter` | 全部 | 报错（必填） |
| `audit` | `Audit` | `Audit` | 全部 | 报错（必填） |
| `approval` | `Approval` | `Approval` | 高危工具 | 有高危工具而没接 → 报错 |
| `http` | `HTTP` | `HTTP` | httpkit/exploitkit/containerkit/fingerprintkit/playbookkit、WinRM | 相关 kit 报错 |
| `fetcher` | `Fetcher` | `Fetcher` | githubkit/oastkit/spacemapkit/icpkit/credkit | 相关 kit 报错 |
| `process` | `Processes` | `Processes` | nucleikit/latkit、SMB/CLI 会话 | 相关 kit 报错 |
| `binary` | `Binaries` | `Binaries` | nucleikit | 相关 kit 报错 |
| `sessions` | `Sessions` | `Sessions` | shellkit/privesckit/internalnetkit/persistkit/cleanupkit/avkit/containerkit | 相关 kit 报错 |
| `evidence` | `Evidence` | `Evidence` | 所有产出证据的工具 | 不报错，但正文进不了证据库（见协议文档 §7） |
| `settings` | `Settings` | `Settings` | githubkit 取 token、nucleikit 取参数 | 相关工具报 unavailable |
| `sealer` | `Sealer` | `Sealer` | 宿主解封凭据 | 不报错 |
| `artifact` | `Artifacts` | `Artifacts` | 大文件暂存（SMB 上传） | SMB 上传报 tool_missing |
| `fingerprints` | `Fingerprints` | `Fingerprints` | verifykit | 相关 kit 报错 |
| `templates` | `Templates` | `Templates` | verifykit | 相关 kit 报错 |
| `template_engines` | `TemplateEngines` | `TemplateEngines` | verifykit | 相关 kit 报错（要求非空 map） |
| `logger` / `clock` / `ids` | 同名 | 同名 | 全部 | 有默认实现，可不接 |

现成适配器（`adapters/`）：`httpx`（`New` = 目标域 HTTP，带 scope+限速+审计；同一包内还有 `Fetcher` 实现）、`exec`（`New` 门禁感知子进程；`NewLocal` 无目标本地命令）、`auditlog`（内存实现，测试用）、`sealer`、`settings`、`limiter`。

## 2. 三种接线粒度

| 方式 | 覆盖 | 需要哪些端口 |
|---|---|---|
| `all.Register` | httpkit + nucleikit | scope/limiter/audit +（nucleikit 还要 process/binary） |
| 分组 helper | `RegisterHTTP` / `RegisterNuclei` / `RegisterVerify` / `RegisterGithub` / `RegisterOAST` / `RegisterSpacemap` / `RegisterICP` / `RegisterFingerprint` / `RegisterTemplate` / `RegisterPlaybook` / `RegisterToolParse` / `RegisterExploit` / `RegisterSession` / `RegisterContainer` / `RegisterLateral` / `RegisterPostExploitation` / `RegisterCred` | 见每个 helper 的注释 |
| `all.RegisterFull` | 21 个 capability、71 个工具 | 上表除 `artifact` 外的全部 |

两个刻意留在 `RegisterFull` 之外的：

- `all.RegisterRecon(reg)` —— `reconkit` 需要宿主在构造后注入 provider 与 `AssetSink`，`capkit.Deps` 装不下。
- `all.RegisterEnterprise(reg, resolver)` —— `enterprisekit` 的 `ProviderResolver`（从宿主会话保险库取 cookie/账号）必须显式传。

按需裁剪更稳：给前端/agent 暴露的工具越少，schema 越少，误用面越小。建议先 `Register` + `RegisterSession` + `RegisterExploit`，跑通闭环再加后渗透。

## 3. 三个必接的宿主实现

### 3.1 ScopeChecker —— 授权范围

```go
type ScopeChecker interface {
    Check(ctx context.Context, t Target) error   // 不通过就返回 capkit.ScopeDenied(...)
}
```

要点：
- 每次调用前 runtime 会先用 `ToolSpec.ExtractTargets` 从输入里抠出目标，你只需判断「这个目标在不在本项目的授权范围」。spoof 过的目标也算。
- 返回的错误必须是 `capkit.ScopeDenied`：这样信封的 `Status` 才会是 `blocked`、`code=scope_denied` 且 `retryable=false`，agent 才不会死循环重试。
- `Target.Kind` 有 `url`/`host`/`ip`/`cidr`/`domain` 五种；CIDR 目标（内网扫描）建议按网段授权，不要按单 IP 展开。

### 3.2 Approver —— 人工确认

```go
type Approver interface {
    Require(ctx context.Context, req ApprovalRequest) error
}
```

- `runtime.Config.RequireApprovalAt`（默认 `high`）以上的工具会先过这里。
- 返回 `capkit.NeedHuman(...)` → 信封 `need_human`（前端应显示「等待确认」而不是「失败」）；返回 nil → 继续。
- 高危工具（`session_*`、`*_execute`、`cleanup_apply`、`persist_apply`、`lat_*`）建议走「人工点确认 + 记录确认人」，别用 `AutoApprove`。

### 3.3 EvidenceSink —— 证据库

```go
type EvidenceSink interface {
    Record(ctx context.Context, ev Evidence) (id string, err error)
}
```

- 返回值 `id` 会原样出现在 `Result.Evidence[].id` 里，是前端「看原文」的钥匙。
- `Evidence` 带 `Kind`/`Title`/`Target`/`Request`/`Response`/`Data`/`Metadata`。响应体、命令输出、文件内容都从这里走 —— 这就是为什么 `Data` 能保持 ≤8KB。
- 没接也不会报错，但**正文进不了信封**：`EvidenceRef` 里只剩 `size`/`sha256`/`preview`，前端看不到原文。生产环境必须接。

## 4. 门禁与运行参数

```go
runtime.Config{
    RequireApprovalAt: capkit.RiskHigh,  // 默认；改进程级更严就降到 medium
    IdempotencyWindow: 5 * time.Minute,  // 默认 5 分钟；<=0 关闭缓存
    JobWindow:         15 * time.Minute, // 异步任务完成后可轮询多久（默认）
    JobTimeout:        30 * time.Minute, // 单个异步任务总时长上限（0 = 不限）
}
```

每个调用强制经过 `scope → approval → rate limit → audit`（`gates.Chain`），阶段耗时会写进信封的 `meta.gate_trace`，前端可以据此解释「为什么慢了」。

## 5. 暴露给调用方

### 5.1 直接用 capkit 的通用 HTTP 面

```go
import "github.com/c1ayooo/capkit/runtime/httpapi"

mux.Handle("/capkit/", http.StripPrefix("/capkit", httpapi.New(rt)))
// GET  /tools      工具目录（含 input_schema/output_schema）
// GET  /manifests  能力清单（含 Requires/Settings/Events）
// POST /call       {tool, input, context}
```

它只做协议转换，不做鉴权、不做项目隔离 —— 所以**必须**挂在宿主的鉴权中间件后面。

### 5.2 包一层 BFF（推荐）

宿主自己写 4 个路由，把鉴权结果翻译成 `capkit.CallContext`，其余交给 runtime：

```go
mux.HandleFunc("GET /api/capkit/tools", s.pgCapkitTools)       // 目录，按项目可见性过滤
mux.HandleFunc("POST /api/capkit/call", s.pgCapkitCall)        // 调工具
mux.HandleFunc("GET /api/capkit/jobs/{id}", s.pgCapkitJob)     // 轮询异步任务
mux.HandleFunc("GET /api/capkit/evidence/{id}", s.pgCapkitEvidence) // 证据原文
```

`pgCapkitCall` 的关键几行：

```go
func (s *Server) pgCapkitCall(w http.ResponseWriter, r *http.Request) {
    var req struct {
        Tool    string             `json:"tool"`
        Input   json.RawMessage    `json:"input"`
        Context capkit.CallContext `json:"context"`
    }
    if err := json.NewDecoder(r.Body).Decode(&req); err != nil { writeErr(w, 400, "无效的请求体"); return }

    // 项目归属由会话决定，不信客户端传来的 project_id / actor
    sc := APIScopeFrom(r.Context())     // auth.go: requireAuth 已塞好（Global/ProjectID/KeyID）
    req.Context.ProjectID = sc.ProjectID
    req.Context.Actor = s.capkitActor(r, sc)   // 宿主自己决定：按 API Key 记录或当前登录用户
    if req.Context.TraceID == "" { req.Context.TraceID = newTraceID() }

    res, err := s.capkit.Call(r.Context(), req.Tool, req.Input, req.Context)
    // 注意：即使 err != nil，res 也一定是完整信封，照常返回 200 + result
    body := map[string]any{"result": res}
    if err != nil { body["error"] = err.Error() }
    writeJSON(w, http.StatusOK, body)
}
```

两个坑：

1. **`err != nil` 不等于 HTTP 错误码。** 门禁拦截、工具失败都会同时返回信封和 error。永远 HTTP 200 + `{result}`，让前端按 `result.status` 分支；用 4xx/5xx 会让前端拿不到 `error.hint`。
2. **`project_id` 必须由服务端覆盖。** 客户端传什么都不算数，否则跨项目越权。`APIScope` 只有 `Global/ProjectID/KeyID`（没有操作人），所以 `Actor` 得宿主自己补。

### 5.3 `job_status` 不用自己写

`runtime.New` 会把 `job_status` 注册进去（和 kit 的工具一起出现在 `Tools()` 里）。任何工具调用带 `"async": true` 就转后台，返回的 `data.job_id` 直接喂给它。BFF 的 `/jobs/{id}` 只是把这个工具再包一层 REST 语义，或者干脆让前端直接 POST `/call {tool:"job_status"}`。

## 6. 会话传输（`sessions` 端口）

宿主持有 `capkit.SessionManager`，决定开了哪些传输：

```go
mgr.RegisterOpener("ssh",   &sessionkit.SSHOwner{HostKeyCallback: pinned})            // 22
mgr.RegisterOpener("winrm", &sessionkit.WinRMOpener{HTTP: httpClient, TLS: true})      // 5986
mgr.RegisterOpener("smb",   &sessionkit.SMBOpener{Runner: execRunner, Share: "C$"})    // 445
mgr.RegisterOpener("cli",   &sessionkit.CLIOpener{Runner: execRunner, AllowedCommands: allowlist})
mgr.RegisterOpener("webshell", &shellkit.WebShellOpener{Executor: myWebshellExecutor})
```

设计要点：

- **四种传输同一套契约**，下游 kit（privesc/lat/internalnet/persist/cleanup/av）不认识具体协议。加一种传输 = 实现 `Exec/Info/Close` 三个方法。
- 可选能力靠类型断言探测：`Uploader`/`Downloader`/`Tunneler` 没实现就返回 `tool_missing`，不要报 panic。
- WinRM 的 WSMan 调用就是普通 HTTP，因此**必须**传门禁感知的 `HTTPDoer`，scope 才对目标生效。
- SMB/CLI 必须传 `ProcessRunner`（`adapters/exec`），kit 内不允许 `os/exec`。SMB 的密码走 `PASSWD` 环境变量，不进 argv、不进审计日志。
- `session_exec` 的输出会由工具写进 EvidenceSink（传输自己带 traffic id 时用传输的），所以命令输出超 8KB 也不会丢。

## 7. 接线自检

```bash
cd capkit
go build ./... && go vet ./... && go test ./... && bash scripts/check-imports.sh
```

宿主侧建议再加一条集成测试：`RegisterFull` + 全部端口 stub，对每个工具发一个最小（通常非法）输入，断言返回仍是合法信封。capkit 自己就是这么做的（`runtime/envelope_surface_test.go`），宿主照抄 30 行即可防止升级 capkit 时信封漂移。

再加一条覆盖检查（§8 验收项）：

```go
for _, tool := range rt.Tools() {
    if len(tool.InputSchema) == 0 || len(tool.OutputSchema) == 0 {
        t.Errorf("%s 缺 schema", tool.Name)
    }
}
```

## 8. 总览：一次调用经过什么

```
agent / 前端
   │  POST /api/capkit/call {tool, input, context}
   ▼
宿主 BFF ── 鉴权、项目归属、trace_id ──→ capkit.CallContext
   │
   ▼
runtime.Call
   ├─ 查工具表（未注册 → not_found）
   ├─ ExtractTargets(input) → scope 校验        ← 你的 ScopeChecker
   ├─ approval（风险 ≥ 阈值时）                  ← 你的 Approver
   ├─ ratelimit（per-host）                     ← gates.Limiter
   ├─ idempotency（命中则直接回缓存结果，meta.cached=true）
   ├─ "async": true? → 起后台 goroutine，立刻返回 partial + JobRef
   ├─ kit.Call(ctx, call)                        ← 只经端口访问宿主
   │     HTTP → HTTPDoer（计数）  进程 → ProcessRunner  会话 → SessionManager
   │     证据 → EvidenceSink     配置 → Settings        机密 → Sealer
   ├─ finalize：补 Status/Summary/Meta（工具名、耗时、Requests、gate_trace）
   │            Data 截断到 8KB + Page.Total
   └─ audit finish                               ← 你的 AuditSink
   │
   ▼
{result: <信封>}  ← 前端只认这一份结构
```

## 9. 常见接线错误

| 症状 | 原因 | 修法 |
|---|---|---|
| `runtime.New` 报 `missing ports: xxx requires sessions` | 注册了会话型 kit 但没给 `Sessions` | 用 `RegisterPostExploitation` 就得分组配齐端口，或换更小的注册组合 |
| 高危工具调用直接报错 `approval gate is not configured` | 有 `Risk >= RequireApprovalAt` 的工具但 `Approval` 为 nil | 传 `Approver`（或显式 `gates.AutoApprove()`，仅限测试） |
| 前端看到的响应体是空的，只有 sha256 | 没接 `Evidence` | 接 `EvidenceSink`，并让 `/api/capkit/evidence/{id}` 能取回原文 |
| 加了个新 kit，宿主编译过但运行报 `unknown tool` | 没注册（`RegisterFull` 里没有，或忘记调用 helper） | `rt.Tools()` 打印一遍核对 |
| 目标在内网，工具却报 `scope_denied` | `ScopeChecker` 只授权了单 IP，内网扫描传的是 CIDR | 按网段授权（`Target.Kind == cidr`） |
| 同一个工具连续调用两次，第二次没有真发请求 | 命中幂等缓存（5 分钟窗口） | 属于预期；换 `task_id` 或显式关闭 `IdempotencyWindow` |
